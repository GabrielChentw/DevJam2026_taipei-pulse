# 臺北市無障礙靜態資料使用策略

第一階段產品範圍鎖定臺北市；目前可操作的示範路線是板南線台北車站至市政府。
資料上圖與路線評估分開處理：適合辨識的點位才做互動標記，大型空間資料只在
目前路線附近查詢，避免把 3D 地圖變成無法閱讀的點海。

## 第一版採用

| 資料 | 用法 | 原因 |
|---|---|---|
| 2-1 捷運所有出入口 | 路線附近的小型出口編號圓圈；無障礙出口使用細藍框 | 390 筆皆有 WGS84 座標，可先建立出口層，再掛接電梯與坡道 |
| 2-2 捷運站無障礙設施 | 捷運電梯資訊卡的廁所、站內設施說明 | 有站名與完整設施文字，但沒有座標，需與 2-3 合併 |
| 2-3 捷運電梯／坡道 GPS | 3D 可點擊／觸控標記 | 190 筆、WGS84，可直接上圖，價值與可信度最高 |
| 2-4 捷運電梯位置 | 資訊卡補充文字 | 適合告訴使用者站內與出口電梯在哪裡 |
| 2-5 路緣無障礙斜坡道 | 只查目前步行線附近；作排序加分與互動標記 | 全市 34,684 點，不能全部渲染；附近有點位也不代表正確路口側，因此不作硬性保證 |
| 臺北市公廁點位資訊 | 導覽視角附近的廁所標記；一般公廁為灰色 `WC`，設有無障礙廁位者為藍綠色 `♿` | 有 WGS84 座標與無障礙廁座數，可可靠區分類型；預設關閉並隨導覽視角出現 |
| 臺北市交通管制工程處有聲號誌設置地點 | 視障模式的路線加分；導覽時只顯示步行視角附近的低調「聲」標記 | 191 筆皆有 WGS84 座標與號誌編號；只作友善證據，不把未收錄路口判定為不可通行 |

## 暫不進入第一版路線評分

| 資料 | 決定 | 後續條件 |
|---|---|---|
| 2-6 人行道範圍 | 暫不上圖、不評分 | 24 MB 多邊形需空間索引；下一階段計算淨寬 `SWW_WTH` 與覆蓋率 |
| 2-7 公園無障礙入口 | 暫不載入 | 只在目的地是臺北市公園時啟用，並用寬度、坡度挑入口 |
| 2-8 市場無障礙設施 | 暫不載入 | 只在目的地是市場時啟用，用於廁所、電梯、坡道查詢，不影響一般路線 |

## 路線加分語意

步行段每 18 公尺取樣，查 18 公尺內的官方路緣坡道點位。依「每次穿越至少需要
上下兩次路緣」估算支持程度，再把證據不足量加入輪椅與高齡 profile 的負擔分數。
這項資料的 confidence 固定為 `estimated`，只調整可行路線的排序，不會因缺點位而
直接宣告不可通行。

有聲號誌以步行線 28 公尺內的點位估算路口支持比例，僅套用於 `low_vision`
profile。資料缺少或附近沒有點位時增加排序負擔，但不作硬性排除，因為點位鄰近
不代表實際穿越方向一定具有語音提示，開放資料也可能有更新時間差。

原始 TWD97 點位轉為 WGS84 後，資料包只保留示範走廊附近資料。重新匯入方式：

```powershell
py -3 tools/import_accessibility_data.py "C:\path\to\accessibility_data" `
  --public-toilets-csv "C:\path\to\taipei_public_toilets.csv"
```
